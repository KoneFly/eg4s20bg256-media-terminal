## 原因与证据边界

日志显示 RTL 产生 11 个 multiplier macro，映射后为上述 DSP 数量；虽然主乘法寄存器复用，其他整数表达式仍被综合成乘法宏。宽 integer 计数/运算、动态字段选取和分散 RAM 端口也形成较多 mux。日志确认推断出六个 BRAM 状态存储，宽记录经物理拆分占用较多 9K。

以上是结合日志和源码的重构判断，尚未逐实例完成面积归因；不能承诺某一项修改的确定节省数量。

## 保持现有规格的重构路径

1. 所有索引改为实际所需的有限位宽，显式扩展算术符号，避免 32bit 通用选择器。
2. 常数乘法用移位加法；所有必要可变乘法复用同一 16×16 运算单元，不改变 floor/饱和语义。
3. 将状态访问统一为串行 16bit 词接口，按固定地址规划集中存储，避免宽记录物理拆分和多个高扇出字段 mux。
4. 同步 RAM 通过运行时初始化清零，不依赖被忽略的初值；逐项审查 RAM byte-enable 告警。
5. 重构后先对已生成的全部默认黄金逐写口对拍，再重跑独立 TD。资源达到冻结目标后才推进 W1。

候选内部地址规划（与对外 T1/T2/P 无关，不改变任何对外字段）：

- bank A：2048×16，trace 0..1023、startF 1024..1151、node 1152..1407、bar 1408..1663、prev 1664..1727；
- bank B：2048×16，每粒子 16 字，包含原 168bit 历史、energy/life、Q4 位置和速度；对外 P 仍只发布冻结的 12 字。

物理 ERAM 类型和块数仍需 TD 测量；这里的形状是重构计划，不是资源 PASS。原粒子数、历史点数、分辨率、坐标表示、默认参数、正式端口和逐位判据保持冻结。
