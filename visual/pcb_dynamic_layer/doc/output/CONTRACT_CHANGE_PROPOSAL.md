# M6 动态层契约最小修订建议

> 最后核对日期：2026-10-04  
> 维护者：pcb_dynamic_layer 执行方  
> 状态：用户于 2026-10-04 回复“确认”，本方案获准实施；具体实现/验证状态另见 run_report。

## 建议决策

以只读 `pcb_model.js` 的逐像素最大值、裁剪顺序和 S2 `packState()` 为权威，修订本任务的内部行缓存格式及黄金缺陷。候选格式已完成模型层的容量与像素还原检查；尚无 RTL 或 TD 实测证据。

修订范围仅为本任务包的 `doc/brief`、本任务黄金脚本和随后新建的 RTL/TB/sim/td_run 产物。P 表仍为 2048×16，W1/W2 正式端口按现有声明，粒子/历史点/分辨率/线宽按冻结值保留。

## 1. 行区段改为按亮度保存的紧凑记录

建议替换 `INTERFACE_SPEC.md` §5.3 及相应预算/验收条款：

```text
SPAN_POOL_DEPTH = 6144
SPAN_REC_BITS   = 24

record[ 9: 0] = x0                // 0..639
record[15:10] = length_minus_one  // 长度 1..64 像素
record[23:16] = luma

row_base[0..479]  : 13bit，指向该行的首记录
row_count[0..479] : 10bit，0 表示空行
```

行记录按 y、x 顺序连续保存，省去每记录 next 指针。不同 primitive 重叠时先逐像素取最大亮度；只合并亮度相同且相邻的像素。长度超过 64 的同亮度区段拆分为多个记录，保证任意 640 像素行均可表示。扫描输出只访问已准备好的当前行数据。

当前审计的紧凑记录最大数量及其帧号见 `sim/startup_audit/audit_result.json::candidate_compact_24_spans` 和 `capacity`。单粒子夹具及饱和前 16 帧，共 17 个完整光平面，通过该记录格式打包/解包逐像素还原；这些是模型检查，不是 RTL 对拍。

候选池的逻辑位数为 6144×24=147456bit，行目录为 480×23=11040bit。物理映射仍以 TD 的实际 ERAM32K/9K 数量为准，保留原行区段池 ≤6 块 ERAM 的目标，不能根据逻辑位数宣布资源 PASS。RTL 构建阶段仍禁止全屏帧缓存和有效像素期间遍历全部线段。候选数据的全屏数组只用于离线参考审计。

这项修订同时改变了内部记录位宽和逻辑深度，必须重新签发；不能把它记成对现有 4096×40 契约的等价实现。W1-07 的容量压力用例也需对应新深度。

若坚持原 4096×40 格式及“所有相邻区段统一最大亮度”规则，就必须由视觉规格方批准改变像素黄金与观感基线；现有逐位验收目标无法同时保留。该路径不建议采用。

## 2. 更正任务黄金

- `addPixel()`：先检查基础点是否在屏内，越界点直接返回；屏内点再向 3×3 邻域贡献并裁剪邻点。
- `putByteWord()`：四个输入分别 `&255` 后再移位/或运算，使 coreQ=256 编码为 0，不侵入 ovK。
- `overlay_hit.bin` 保存当前的命中掩码；完整连续帧的 `overlay_valid.bin` 保存输入有效的参考序列，TB 按延迟映射输出。缺口刺激另存输入调度。
- 行区段文件按新记录格式保存，并在生成器中执行像素还原检查；meta 的数量应统计真实存储记录，不能继续只统计非零连通区域。
- 生成器记录上游 SHA256、场景刺激和打包布局，补齐合同场景；参数场景采用独立配置参考，不从 DUT 状态或输出产生期望。

更正裁剪后重新运行完整容量审计及合同场景。当前容量数字来自尚未更正的签发黄金，不能作为修订后黄金的最终容量证据。

## 3. 明确 valid、标记与合体

- W1 独立输出契约保持 `overlay_valid[n+647]=in_valid[n]`，包括断流与帧尾排空；任何有效输出都对应 647 拍前的真实输入有效。
- W1 正式端口保持现有声明。内部延迟 SOF/EOL 可供 TB 检查；S6 合成级从原像素流独立延迟元数据 647 拍。删除当前“W1 通过未声明端口向合成级传递标记”的歧义。
- 合体台显式接入 overlay_hit，覆盖条件为 `overlay_valid && overlay_hit`；无命中时透传原 S2 输出。
- S2 647 拍对齐仅承诺完整连续输入帧。W1 的自然时钟断流检查独立执行；任意断流下的 S2/W1 重对齐留给 S6 的明确适配任务。若当前任务必须包含这一适配，应重新签发范围，不能修改 task_045。

## 4. 给独立任务明确执行规则

建议给本包签发以下例外：

> pcb_dynamic_layer 为禁止主线集成的独立 RTL 任务，允许上板前执行本包的 Verilator lint、P0/L0/L1、变异验证及连续全帧离线 smoke；不以这些结果表述板级 PASS。仿真统一使用 WSL Ubuntu Verilator，不使用 iverilog。

修正 TASK_KICKOFF 的入口链接。补齐 task 自己的 `sim/run.sh` 与 `td_run` Tcl，并在本包记录签发身份。TD 独立资源/时序测量遵循冻结源文件列表；本轮不生成或登记主线上板 bit。
