# A2 上板记录复查与重新读页流程（2026-10-06）

结论：A2 无线稿，未通过硬件验收；现有读数尚不能确认来自加载快照，不能据此认定停在 BOOT。先核对诊断 bank 和 KEY1 响应，保持 A2 RTL、MISO 两级缓冲及受控卡不变，不重出位。

本复查针对规格方的 `A2_PROBE_RESULT_AND_NEXT_20261006.md`，保留原文。原文 §6 的要求按“先取原生网表证据、禁止盲改”执行；其 §2～4 的推断作为待核验假设，不当作已成立的板上事实。

## 1. 用户直接回传的事实

- 上电后设置 SW0=1、页 000，见 `d0 05462`。
- 设置 SW0=0，按 KEY1 并放开，屏幕一直无线稿；用户描述 d0 一直为 05462。
- 所称 P1～P6 全零，P7=05401。
- 尚未确认读 P1～P7 时是否重新设置 SW0=1，也未确认 KEY1 按住期间数码管是否熄灭。
- 本次回传没有明确提供 A2 的 `60070` 或其他错误码，也未提供 10 秒触发时刻。因此不能把 R2 的 10 秒 0x46 现象直接移作 A2 实测事实。

候选文件：`deliverables/M6_FDI_A2_20261005_7B97635A.bit`，636626 字节，当前 SHA256 复核为 `7b97635aadd6fa4ebab8f3fc598f195cde5bafcdf6b6968bf105ac62284cd57c`。上板加载对象以用户操作记录为据；数码管识别值不能替代位文件哈希。

## 2. 文档需要修正的判断

| 原判断 | 复查结果 |
|---|---|
| 05462 表明完整拨码映射自检通过 | 只确认当时出现 A2 识别值；不能证明 SW0 后续翻转及三个页位都正确。 |
| P1=0 表明 store=BOOT | 只有 SW0=1 的真实快照页才有此含义。若 SW0=0，显示来自普通 HDMI/频谱诊断。 |
| P4/P6 全零说明从来没有与 SD 卡交互 | 完成标志全零不证明未开始交互；复位/无 CTRL 时钟也可能使快照保持零。必须先确认读到了快照，再联合状态位、等待位及复位响应判断。 |
| 已排除 INIT、SECTOR_START 和 MISO 假设 | 当前 bank 未确认，排除均不成立；MISO 实验结果仍待正确观测，不据此回退或继续改缓冲。 |
| A2 与 R2 相同，都是 10 秒报 0x46 | 两者都无线稿已观察到；A2 的错误码和计时尚未提供，内部挂起点是否相同未知。 |

`v9_m6_hdmi.v` 的普通诊断 P7 固定为 5401。P0=good、P1=video_locked、P2=bad、P3=old_packets、P4=gaps、P5=replaced、P6=online；这些项在尚无有效活动时可以为零。因此“多页零 + P7=05401”与普通 bank 相符，但在核对开关前只列为读页范围疑点。

A2 顶层显示优先级是：reset → 60001；否则 SW0=1 → 快照；否则加载错误码非零 → 60000+错误码；否则 KEY2 诊断或普通 HDMI/频谱诊断。只要实际 `sw[0]` 已为 0、时钟/刷新正常且等待超过 0.3 秒，就不应持续显示 `d0 05462`。这个不一致应先澄清，不能跳过后直接解码 BOOT。

## 3. 原生网表证据：两个比较常量均正确

新增只读复查脚本：`scripts/review_a2_readback.py`。它展开门级 AL_MAP_LUT 的 INIT 真值表，再独立沿最终 `route_netlist.v` 的 MSlice/LSlice LOGIC f 输出展开，检查两者的全部 29 个 watchdog 输入约束逐位相同。

| 条件 | 门级实际比较常量 | 最终 route 比较结果 |
|---|---|---|
| 启动延时 | 499999 = 0x0007A11F | 相同，29 位全部匹配 |
| 启动总超时 | 499999999 = 0x1DCD64FF | 相同，29 位全部匹配 |

门级输出分别是 `u_display/u_label_store/state_reg[0]_syn_257` 和 `..._syn_241`。最终物理输出分别在 `u_display/u_label_store/u_mem/mux74_syn_753` 的 f[0] 和 `u_display/u_scan/u_renderer/cap_trace_reg[25]_syn_4` 的 f[0]；物理打包名称跨模块不改变其输入函数，复查采用实际连线及 INIT，不按实例名称猜测功能。

证据保存于 `A2_PROBE_STATIC_REVIEW_FINAL_20261006.json`，含 gate/route/bit 的 SHA256、29 位条件、物理比较器完整路径与单元内容。本构建没有发现文档 §4(a) 怀疑的启动常量求值错误；不据此改 integer 位选写法。

## 4. 状态编码与快照

TD 的 SYN-1067 记录里，加载范围内重编码的是 byte_phase 和 reader 内部 byte engine；没有加载主 state 的重编码记录。

门级实际为四个 `state_reg[0..3]` FF，Q 分别为 `u_display/u_label_store/state[0..3]`。四个 `debug_snapshot_reg[0..3]` 的 D 分别直接连接上述四个 Q，无低四位截断 one-hot 状态表的路径。初始化状态为四位 0000，主状态的源码编号仍对应 A2 解码表；最终 route 也保留 state[1:0]、state[2]、state[3] 的 Q 输出。

门级 LUT 组合求值还检查了 BOOT 的下一状态：watchdog=499998 → 0000；watchdog=499999 → 0001。其他未给定信号按未知量保守传播，两个结果均可确定。这个结果支持启动条件在网表中存在，不能证明板上 CTRL 时钟或复位实际正常。

快照在非 ERROR 时连续采样，进入 ERROR 当拍采旧态并冻结；复位则全部清零。因此即使正确 bank 内真的全零，也不能单凭零判定“watchdog 已数满 10 秒但 BOOT 永不退出”。该推断还需要本次实际错误码、复位释放、CTRL 运行等证据。

## 5. 无改位的真卡复测步骤

主板继续使用 A2 / 7B97635A；副板保持已验 7175ECC3。使用原受控 TF 卡。

1. KEY2、KEY3 保持放开。把页设为 000，在 SW0 的两个位置之间切换，每次等待至少 0.3 秒。明确记录完整前缀及数字；诊断 bank 应为 `d0 05462`，另一位置应离开此识别值。
2. 用步骤 1 确认的普通 bank 位置，按住 KEY1 约 1 秒，记录数码管是否熄灭。A2 的数码管及输出寄存器直接由 key1 低电平异步复位，按住时应消隐。放开后等待至少 12 秒，记录完整显示及屏幕，明确是否见 60070 或其他错误码。
3. 不再次复位。把 SW0 切回步骤 1 确认的诊断 bank，并保持为 1，逐页读取。每页至少等 0.3 秒，正常前缀应为 d1～d7；P0 应仍为 d0 05462。记录实际前缀，避免把普通 P 页简称与诊断页混淆。

| 诊断页 | RTL sw[3:0]（从高位到低位） |
|---|---|
| d0 | 0001 |
| d1 | 0011 |
| d2 | 0101 |
| d3 | 0111 |
| d4 | 1001 |
| d5 | 1011 |
| d6 | 1101 |
| d7 | 1111 |

这里 0/1 指 FPGA 实际电平，不能直接把拨码丝印 ON/OFF 当作电平。当前 ADC 对应 sw[0..3]=C8/C7/C6/C5，注释为板上 SW1～SW4；本文 SW0 始终指 RTL sw[0]。key1 的当前 ADC 引脚为 B2。未确认电平时，先通过显示 bank 的实际响应核对，不改约束。

回传格式：`SW0 两位置的完整显示=.../...；KEY1 按住是否灭=...；放开12秒后=...；d1=... d2=... d3=... d4=... d5=... d6=... d7=...；屏幕=...`。

若 bank 切换不响应或 KEY1 不消隐，先核对开关/按键实际操作与烧录对象。若确认诊断 bank、复位有效，仍全部快照零，再沿 CTRL PLL 输出、复位同步与快照网表查证；这只是条件分支，不是当前已认定根因。取得有效快照后再决定单点修复，每个新位仍须真卡线稿出现并稳定至少 10 分钟。
