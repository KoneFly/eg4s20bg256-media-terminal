# M6-FDI 首块上板故障：0x46 启动看门狗超时（2026-10-05）

> 编制：浮浮酱（规格/验收方）｜ 对象位：`M6_FDI_R2_20261005_6B810152.bit`
> 状态：**硬件 FAIL，功能未验收**；执行方需据此排查并回归。

## 1. 现场现象（主人实测）

| 项 | 观察 |
|---|---|
| 上电 | 数码管先显示 `05401`（版本，说明烧的是本位） |
| **约 10 秒后** | 转为 **`60070`**（故障码 0x46） |
| 屏幕 | 无 PCB 线稿（无标签底图） |
| 副板 | 已烧 7175ECC3，两板直连 |

## 2. 独立核验（浮浮酱）

| 项 | 结论 |
|---|---|
| 受控 TF 卡 | ✅ **逐字节合格**：标签区 CRC32 = `47E2A01D`、SHA256 = `938219a7…`、BPB/FAT 结构正确、四首 PCM 的字节数与 SHA256 全中（从裸盘读回独立解析） |
| 引脚 | ✅ 与 **05501**（真卡可读可播）完全相同：A14/B14/A13/A12，LVCMOS33 |
| **判别实验** | ✅ **05501 用同一张卡能读卡播放** ⇒ **卡、卡槽、引脚、SPI 电气通路全部无问题** |
| ⇒ 定位 | **故障在本 M6-FDI 新增加载链内部** |

## 3. 故障码含义（读自 RTL）

`fdi_label_store.v`：`BOOT_TIMEOUT_CYCLES=500000000` ÷ 50MHz = **10 秒**；状态机未在限时内走到 `READY` 即报 `8'h46`。

| 码 | 显示 | 含义 |
|---|---|---|
| 0x81/0x82/0x83 | 60129/130/131 | init 失败：CMD0 响应异常 / ACMD41 不就绪 / 命令超时（无卡） |
| **0x46** | **60070** | **看门狗超时——流程卡死（非报错退出）** |
| 0x47 | 60071 | READY 后 SDRAM 服务超时 |
| 0x40/0x41/0x42/0x43 | 60064~60067 | 头字节错 / 文件 CRC32 错 / 字节数不符 / 相位或写背压冲突 |
| 0x48/0x49 | 60072/60073 | 读回 CRC32 错 / CHECK 阶段异常 |

**关键推论**：所有"数据读错"的路径都有专属错误码（0x40~0x43、0x48、0x49），**一个都没触发** ⇒ 不是读错数据，而是**卡在某个握手/等待上**（`sector_valid`、`eng_resp`、`mem_busy`、或 init 内部 `cmd_done`）。

## 4. 已排除项（勿重复投入）

| 项 | 依据 |
|---|---|
| 卡 / 卡槽 / 引脚 / 电气 | 05501 同卡可读可播；卡逐字节验证 |
| SPI/SD 驱动层 | `fdi_sd_*` 与 052 第五步（真卡已验证）模块**改名副本**，尺寸逐项吻合 |
| 片上 SDRAM 引擎 | `fdi_sdram_cmd_engine`（22988B）与 043 主线**已上板验证**的 `sdram_cmd_engine`（22906B）同尺寸；50MHz/180° 与主线 SDC 记录一致 |
| PLL 与时钟 | C0=125M/C1=50M/C3=50M@180° 全部 ENABLE；`rst_out=!locked`（锁定后放复位） |
| 看门狗参数本身 | 10 秒对正常流程（仿真 0.497s）绰绰有余 |

## 5. 嫌疑排序（执行方据此定向）

### 5.0 追加实测（2026-10-05 晚）

| 实验 | 结果 | 结论 |
|---|---|---|
| KEY1 复位后再放开 | 10 秒后仍 `60070` | 可复现，非上电偶发 |
| **换另一张 TF 卡**烧本位 | **同样报错** | 排除卡兼容/临界时序 ⇒ **确定性逻辑问题** |

### 5.1 进一步收敛（读 RTL 得出）

`fdi_sd_spi_sector_reader` 中 `assign sector_busy = (state != ST_IDLE);` ⇒ 存储机 `SECTOR_START: if(eng_init && !sector_busy)` 实际**退化为只等 `eng_init`**。

因此"挂起"只可能是下面二者之一：

- **(A) 停在第 INIT 级**：`fdi_sd_init_sequence` 内部状态机等待命令器 `cmd_done` 而**无超时保护**，静默停住（外层 `INIT_POLL_MAX` 预算逻辑根本没机会触发）；
- **(B) 停在 SECTOR_START**：`eng_init` 始终不为 1（SDRAM 引擎初始化未完成）。

两者都**不会触发任何数据错误码**，与实测"无 6xxxx 码、只有超时"完全一致。

### 5.2 头号嫌疑：MISO 4 级 `EG_LOGIC_BUF` 延迟缓冲

依据：

1. 它是本轮**唯一触碰"已验 SPI 层"**的改动（`fdi_sd_*` 其余部分与 052 第五步逐项同源）；
2. 若采样边沿被推偏，命令响应读不出来 ⇒ 命令器**等响应**处静默停住（对应 (A)）；
3. **仿真必然通过、真卡必挂**——门级/行为模型不含这 4 级物理缓冲 ⇒ 恰好解释"模型全过、硬件全挂"；
4. 与"换卡也失败"一致（延迟是确定性的，与卡无关）。

**建议的单点实验（改动最小、判别力最强）**：去掉/缩减该延迟缓冲后重出位，真卡复现一次即知。

### 5.3 次选

- `fdi_label_store` 握手簿记（`req_fire`/`mem_busy`/`write_pending`）死锁；
- SDRAM 引擎 `init_done` 到 `eng_init` 的路径（电平已确认由 ST_TMRD 置位保持，但需实测确认其真的到达存储机）。

## 6. 要求的处置（先观测、后修复）

**第一步（必须）：把黑盒变可观测**——新增一个临时诊断位（或以 sw 页暴露）：

- `fdi_label_store` 的 `state[3:0]`、`sector_number`、`bytes_seen`、`write_index`、`mem_busy`、`write_pending`；
- `fdi_sd_init_sequence` 的内部状态与 `init_done/init_error`；
- `fdi_sd_spi_sector_reader` 的内部状态（是否在等 token/Ncr）。

上板复现，**先确认卡死在哪一级**，再针对性修复；禁止在无观测的情况下盲改。

**第二步：修复后按原门禁回归**（同为真卡上板复现）——线稿出现 + ≥10 分钟稳定。

**纪律要求**：本轮已验证的功能（卡片校验路径、SDRAM 引擎、SPI 驱动）不得改写；改动只落在故障点及其必要的最小面；模型验证不能替代真卡复现（本包 SDRAM 行为模型曾"改为提前一拍以匹配 RTL"，方向相反，须警惕）。
