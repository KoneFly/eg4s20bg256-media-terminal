# A4 校准后板测结论与分层排查（2026-10-06）

**硬件仍FAIL，观测停在标签加载器BOOT等待期。** A4版本d0=05464、d7=65280已由用户确认。d1=65535、d2=59392、d4=64、d5=268、d6=4096保留；最新补读原话为“d3只在四位数中变化，一直变化，明确无信号”。d3没有具体极值，不能推定它已经达到9999；此前“十秒后全都一样”不能继续解释成d3停止变化。KEY1当前运行的起始操作仍未明确重述。

SD初始化观测IDLE、reader观测IDLE、eng_init0、init_ready0；目前未见扇区读取和CRC执行证据。watchdog高位历史仅bit27置位，但bit16历史、499999启动命中、BOOT退出均未记录。若从零按正常29位+1逐拍遍历，此历史不成立；仍须定位初始条件、计数路径、时钟/复位及物理实现，不能直接认定某一种根因。

新增显示侧复核纠正一个潜在误读：**明确“无信号”并不单独证明HDMI时钟损坏。** `v9_m6_scan.v` 的output_de受display_enabled门控；display_enabled只有在首批state_committed、pixel_ready等条件成立后开放。BOOT时标签未就绪，标签像素供应关闭，普通情况下不能开放DE。`axis_pixel_adapter.v` 的axis_s_valid直接等于I_de，HDMI IP没有收到有效视频输入；因此无信号可能是加载卡住的下游表现。这里是基于RTL的因果推断，不是对加密HDMI内部或板上输出波形的实测。

相对于继续向完整工程添加只读探针，下一步改用**已验位对照 + 最小自检 + 逐层接回**。先验证现有75959E68位在同一主板、同一HDMI-B线和显示器上是否仍有稳定图像；基座文件SHA已现场核对，052第四步记录有用户2026-10-04总体验收通过的回填，但不补造逐项实测。该对照可立刻执行，不需要再等新TD构建。

对照正常后，最小工程只保留相同引脚、时钟/复位、独立计数启动自检和不依赖标签的固定视频源，测CTRL进度/频率、16位跨界、9999/499999命中及视频。通过后逐层接入冻结SDRAM引擎、受控TF原驱动及双CRC，最后恢复完整W2/S2链。各级必须真卡/真板复现，具体分支与观测条件见 `doc/brief/BOARD_DIAGNOSTIC_ISOLATION_PLAN_20261006.md`。

本轮新增工作仅为补读归档、静态显示门控复查和对照实验准备；尚未建立最小工程或生成新bit。没有修改RTL、SDC、已有bit、SPI/SDRAM/CRC、W2/S2、上游索引或TF布局。现有完整功能仍是最终交付目标，独立自检不作为裁掉冻结效果的交付。原A4软件封存与部分读数封存保持原样，本记录追加更正和确认。
